---
title: Environment
description: Detect the current runtime environment and branch on it, and auto-load the matching .env files on Node.
---

envapt detects which environment it's running in and exposes it through the `isProduction` / `isStaging` / `isDevelopment` / `isTest` helpers, which work on every runtime. On Node, Bun, and Deno it also loads the matching `.env` files for that environment.

## Detecting the environment

The environment is resolved from the first of these keys with a non-missing value, falling back to development:

`ENVIRONMENT` → `ENV` → `NODE_ENV` → `MODE` → `development`

An empty value is skipped like an unset key. A whitespace-only value is skipped only under strict mode.

`MODE` is last because Vite-family browser builds expose `import.meta.env.MODE` but none of the others, so binding `new PortableSource(import.meta.env)` lets the same helpers work there. See [Browser](/docs/browser).

Read it as a string, or through boolean helpers for the common checks.

```ts twoslash
import { Envapter } from 'envapt';
// ---cut---
Envapter.environment; // Environment
//        ^?
Envapter.isProduction; // boolean
Envapter.isStaging;
Envapter.isDevelopment;
Envapter.isTest;
```

<Callout type="info">
    The environment is one of `'development'`, `'staging'`, `'production'`, or `'test'`. `Environment.Production` is
    `'production'`, and the other three members follow the same pattern. Matching is case-insensitive, so `PRODUCTION`
    reads as `'production'`. Any other value, or no key set at all, falls back to `'development'`. Set `Envapter.debug = 'warn'`
    to log that fallback.
</Callout>

## Branching on the environment

Use the helpers where behavior should differ per environment.

```ts twoslash
import { Envapter } from 'envapt';
// ---cut---
const logLevel = Envapter.isProduction ? 'warn' : 'debug';
//    ^?

if (Envapter.isDevelopment) {
    // wire up dev-only tooling
}
```

## Overriding detection

Set `Envapter.environment` to pin the environment explicitly, regardless of what the env vars say. It takes an `Environment` value or any string, matched case-insensitively.

```ts twoslash
import { Envapter, Environment } from 'envapt';
// ---cut---
Envapter.environment = Environment.Staging;
Envapter.environment = 'production';
```

Setting it reloads the `.env` files for that environment.

<Callout type="tip">
    Set it once, at the top of your entry file. Anything you read into a variable before that keeps the old value.
</Callout>

## Per-environment `.env` files

<Callout type="info">
    The cascade reads files from disk, so it runs on Node, Bun, and Deno only. Cloudflare Workers and the browser have
    no filesystem and no cascade. You bind an environment source instead. See [Sources](/docs/sources).
</Callout>

For the detected (or overridden) environment, envapt layers a dotenv-flow cascade, loading the first file that exists at each level, highest precedence first:

1. `.env.${env}.local`
2. `.env.${env}`
3. `.env.local`
4. `.env`

So in production it reads `.env.production.local` → `.env.production` → `.env.local` → `.env`. Values from higher-precedence files win. Missing files are skipped.

<Callout type="warn">
    Precedence is **most-specific-wins**: `.env.production` outranks `.env.local`, the same order dotenv-flow uses.
    Next.js loads `.env.local` above `.env.production`. The intent is that a committed `.env.production` stays
    authoritative for that environment even if a stray `.env.local` is present.
</Callout>

## Custom profiles

When your per-environment files live elsewhere, `configureProfiles` layers explicit paths on top of the cascade for the environments you name. Earlier paths in the array win. On the portable build these no-op by default, see [Compatibility](/docs/compatibility).

```ts twoslash
import { Envapter } from 'envapt';
// ---cut---
Envapter.configureProfiles({
    production: { paths: ['config/prod.env', 'secrets/prod.env'] },
    staging: { paths: 'config/staging.env' }
});
```

<Callout type="danger">

A configured path must exist, and a missing one throws `EnvFilesNotFound`. envapt checks only the active environment's paths. The auto-cascade skips a missing file.

```ts twoslash
import { Envapter } from 'envapt';
// ---cut---
Envapter.environment = 'development';
Envapter.configureProfiles({
    development: { paths: 'config/dev.env' }, // throws here if this file is missing
    production: { paths: 'config/prod.env' } // not checked yet
});

Envapter.environment = 'production'; // throws here if config/prod.env is missing
```

</Callout>

Set `useDefaults: false` to load **only** the configured paths and skip the auto-cascade entirely.

```ts twoslash
import { Envapter } from 'envapt';
// ---cut---
Envapter.configureProfiles({
    production: { paths: 'config/prod.env' },
    useDefaults: false
});

Envapter.resetPaths(); // back to the pure cascade
```

To bypass environment-based selection altogether and load a fixed set of files, set `Envapter.envPaths` directly, covered in [Configuration](/docs/configuration).
